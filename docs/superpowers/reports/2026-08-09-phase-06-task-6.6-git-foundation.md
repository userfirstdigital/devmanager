## Correction delivered

### Sealed operation authority

- `GitOperationPermit` is a non-`Clone` operation object. Its host variant
  retains the opaque Workspace/resource/controller/connection markers, exact
  task/workspace/repository-static identity, action generation, retained
  graph/root handles, endpoint lease, one absolute deadline, and bounded
  limits. A live bit or copied path is not sufficient.
- Host read, mutation, and service-mutation permits validate the exact
  execution policy. Destructive permits also bind capability, plan digest,
  remote policy, remote name, and the complete command-argument digest.
  Authority markers use the issued action generation and exact identity rather
  than a generic live boolean; host deadlines are clamped to the authority's
  absolute expiry and operation limits.
- Host liveness itself is marker/lease-only; filesystem proof stays in the
  deadline-aware graph validator, and mutable host identity advances only
  after successful post-effect graph, endpoint, child, and operation checks.
- Graph admission, handle pinning, endpoint leasing, bounded file reads, and
  baseline writes all perform final deadline checks before returning or
  changing authority state.
- The legacy repository `confirm` and service-mutation entry points are
  sealed fail-closed shims. The typed `run_service_mutation_with_permit` path
  is the only executable service-mutation seam; the only issuers in this
  correction are `cfg(test)` fixtures. Production without a later host issuer
  returns typed `AuthorityUnavailable`.
- Repository status, operation-state, service path validation, file reads,
  config/remote reads, and endpoint admission all consume the owned read
  permit. `operation_state` now validates before and after its state reads.

### Exact repository and endpoint graph

- Admission and revalidation retain exact root, linked-gitdir, commondir,
  config/config.worktree, HEAD/index/packed-refs, refs/logs, objects,
  alternates, packs, and linked-worktree metadata identities. Optional
  descriptors and `.git/worktrees` are absence-baselined, so late creation,
  replacement, and swap-and-restore fail closed on reads.
- Graph transitions are operation-specific. Only the exact mutable state
  needed by stage/commit/branch/fetch/pull is adopted after a successful
  authorized transition; read-only and unrelated graph substitutions remain
  rejected. Static alternate content is recursively bounded and retained.
- Repository graph and mutable-directory fingerprints hash exact platform path
  bytes, including non-Unicode names, rather than a lossy display conversion.
- Local and `file://` endpoint policy admission and revalidation retain the
  endpoint/ancestor handles and identities, enforce workspace containment and
  reparse rejection, and check the caller-owned deadline before and during
  handle retention and before/after child effects.

### Process and reader ownership

- One permit deadline flows through executable admission, graph and endpoint
  checks, spawn, output limits, reader joins, process settlement, and cleanup.
- Unix process-group and Windows Job ownership remain authoritative through
  child zero. Normal managed cleanup does not use raw `Child::kill()` or
  PID-only cleanup. The one pre-Job Windows setup-failure fallback uses the
  already-owned `Child` process handle, then bounded-waits and reaps it; it
  cannot target a reused PID. If the platform authority is unavailable after
  setup, cleanup is visible and fail-closed.
- Reader workers use cancellable pipe I/O and bounded joins. A reader that
  ignores cancellation is retained by a bounded visible reaper; its slot
  remains occupied until joined, preventing unbounded detached workers.

### Latest source-hardening pass (focused verification pending)

- Linked-worktree graph admission now validates reciprocal `gitdir` and
  `commondir` descriptors against the selected common store, retains the
  linked metadata graph, and admits the exact per-worktree `HEAD`, `index`,
  `ORIG_HEAD`, `logs`, and `refs` transition paths.
- `reset` has its own transition allow-list for legitimate state, refs, and
  reflog changes. Existing bound objects cannot be deleted or replaced by a
  mutating child; newly-created object fanout/pack entries remain subject to
  the operation-specific allow-list.
- Graph depth, approved-root, mutable-entry, worktree-entry, pack, ref/log,
  node, byte, and deadline checks now run before and during canonicalization,
  enumeration, and bounded reads. Executable bindings and Windows no-delete
  ancestor handles remain owned by `ManagedGitChild` through settlement.
- Mutable Git-dir containers retain a shallow direct-entry baseline while
  object stores retain recursive content baselines; the containment test for
  nested mutable graph roots is directionally correct, so empty stores do not
  spuriously fail their first pre-spawn validation.
- A real temporary-repository service test exercises a retained in-workspace

  Reader-worker timeout paths now transfer every live join handle to the
  bounded visible reaper; no `JoinHandle` is dropped or detached.
- Read permits now start a fresh bounded deadline at each operation boundary,

- Service remote argument binding accepts only the typed service forms and

## Remaining platform HOLDs

- Windows Job setup-failure cleanup is the owned `Child` handle
  (`Child::kill` + bounded wait/reap). It cannot target a reused PID,
  but it is not Job/process-group cleanup. Normal managed cleanup stays
  Job-based. If Job claim fails after spawn, cleanup is visible and
  fail-closed.
- Unix spawn does not re-query the launched image path/identity the way
  Windows `QueryFullProcessImageNameW` does. Unix ownership is
  process-group + held executable fd.
- Non-unix/non-windows: no Job/process-group; settlement is a no-op;
  reparse rejection is symlink-only; argument/path NULs fall back to
  lossy display.
- Local/file remote *argument* strings and `RepoPath` Windows
  `from_path`/`to_path_buf` still use lossy display. Authority matching
  for local remotes still requires the exact retained endpoint-lease
  `Arc`; graph/workspace identity uses exact OS units.
- Config/Workspace host issuer is still absent. Production mutations
  fail closed until that union issues a typed permit.
