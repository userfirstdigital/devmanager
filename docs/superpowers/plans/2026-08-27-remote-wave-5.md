## Native shell migration

1. Introduce a bounded `BTreeMap<HostId, HostUiState>` inside the canonical shell.
   A slot owns its runtime, model, inbox, task list, interaction epochs, cockpit,
   provider/config/services projections and pending query/action state. Keep
   browser/terminal local authority explicitly scoped. No UUID remapping, raw
   domain-model merge, implicit active-host write fallback, or second bus.
2. Keep one global recursive workspace and `TaskSurfaceRegistry<HostTaskKey>`.
   Selection, pane callbacks, semantic/accessibility IDs, search results and
   project scope carry owner identity. Raw TaskId is extracted only after the
   owning slot has been selected for a wire request.
3. Keep one active composer with mandatory `composer_owner`. Qualify drafts,
   attachments, pending first-send/reopen/title workflows, errors, receipts and
   repository selection. Load legacy layout/drafts through the exact local
   profile mapper only; save the existing keyed schemas without another format.
4. Merge presentation rows, not ClientModels. Every row includes host label and
   HostTaskKey; the same raw task ID on two hosts is two distinct rows and panes.
   Done stays compact at the bottom; opening it never restores it. Archives stay
   out of the ordinary rail. Plain selection replaces the focused pane; Shift
   selection adds/removes. Preserve resize pins and multi-folder projects.
5. Drain host runtimes round-robin under a fixed per-host quota, validate the
   complete projection owner before all side effects, then update only its slot.
   An offline host retains cached presentation but no mutation authority; it
   must neither block another host nor erase another owner's surfaces.
6. Connect trusted hosts through the existing profile-rooted RemoteTrustStore
   and HostFleet. Reconnect factories preserve authenticated identity and may
   not use the local IPC fallback. Native Settings exposes trusted-host list,
   explicit endpoint + pairing code enrollment and forget/disconnect. No change
   to OS certificate trust, firewall rules or installed production profile.

## Verification boundary

### Trusted-PC controller wiring after the owner migration

- Reuse `PendingHostBootstrap` / `NativeHostBootstrap` for cancellation-owned
  off-UI construction; do not add an unowned Tokio task returning a runtime.
  Enrollment and reconnect return the existing `HostClient` into the existing
  shared `HostFleet`, then attach that exact slot to the native shell.
- Resolve the same explicit config root as the owning host. In production,
  `IsolatedDevProfile::root()` is already the resolved application config root.
  For an isolated profile, use `resolve_app_paths(host_config_base(),
  AppProfile::named(named_profile()), BuildKind::Debug).root`. Do not append a
  second production/profile suffix or use ambient app-data from the UI worker.
- Use `list_trusted_hosts`, `pair_enroll_and_connect`, `connect_trusted_host` and
  exact-record `forget_trusted_host`. No plaintext credentials in view models,
  no trust-by-discovery and no implicit certificate or firewall changes.
- A healthy remote requiring resync uses its current fleet connection. A lost
  connection uses a factory bound to its explicit store root and public host ID,
  preserving the stored Noise pin and assigned client identity. Never attempt
  local IPC as a remote fallback. Retry only that host under bounded backoff.
- Rejected attachment returns ownership to the caller. A non-owning runtime
  wrapper must not detach or remove a shared fleet slot. Forget fences/removes
  that owner before deleting its exact persisted record, and leaves unrelated
  panes, cached drafts and unresolved operation outcomes intact.
